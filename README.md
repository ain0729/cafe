# CAFE — 회원 · 카드 결제 · 스탬프

## 실행

Node.js 24 이상이 필요합니다. 별도 패키지 설치는 없습니다.

1. `start.bat`을 더블클릭합니다. (또는 이 폴더 터미널에서 `npm start`)
2. 창을 열어두고 브라우저에서 `http://localhost:3000`을 엽니다.
3. 종료는 서버 창에서 Ctrl+C. `app.js`를 Run Code로 실행하지 마세요.

회원·주문 기능은 `index.html`을 직접 열어서는 동작하지 않습니다.
회원·주문·스탬프는 `data/cafe.sqlite`에 저장됩니다. 서버 재시작 뒤에도 남습니다.
데이터 폴더는 개인정보를 포함하므로 공유하지 말고, 서버를 중지한 뒤 데이터 폴더 전체를 백업하세요.
OneDrive 동기화 폴더의 DB를 여러 컴퓨터에서 동시에 열지 마세요. 운영 시 단일 서버의 로컬 디스크로 옮기세요.

## 카드 결제 설정

`.env.example`을 `.env`로 복사하고 토스페이먼츠 **결제창 API 개별 연동**의 같은 상점 테스트 클라이언트 키(`test_ck_...`)와 시크릿 키(`test_sk_...`)를 넣은 뒤 재시작하세요. 결제위젯 전용 키와 다릅니다.
비밀키는 채팅, 프런트엔드 파일, Git에 넣지 마세요. 설정이 없으면 카드 결제 버튼은 비활성화됩니다.
테스트 모드 결제와 스탬프도 DB에 저장되므로 운영 전 테스트용 DB와 운영 DB를 분리하세요.

실제 결제는 결제사 가맹점 등록·심사와 운영 키가 필요합니다. 공개 HTTPS 서버에서 `BASE_URL=https://실제주소`, `HOST=0.0.0.0`, `ALLOW_LIVE_PAYMENTS=true`와 같은 상점 운영 키를 설정하세요. 프록시로 HTTPS를 제공해야 합니다. 외부 접속 URL은 BASE_URL과 정확히 일치해야 합니다. 로컬 전용 실행은 localhost를 사용하세요.
현재 가맹점 키가 없어 실제 결제창·실카드 승인 확인은 수행하지 않았습니다. 테스트는 결제사 응답을 모의한 자동 테스트입니다.

공식 문서: https://docs.tosspayments.com/guides/v2/get-started/llms-quick-reference

## 회원 및 관리자

이메일·이름·10~128자 비밀번호로 가입합니다. 비밀번호는 scrypt 해시, 세션은 HttpOnly 쿠키입니다.
관리자 지정은 **서버를 로컬 상태로 유지한 채 먼저 본인 계정을 가입**하고 `.env`의 `ADMIN_EMAIL`에 그 이메일을 지정한 다음 재시작하세요. 로그인 후 `http://localhost:3000/admin`에서 주문을 확인합니다.
이메일 소유 확인·비밀번호 재설정은 아직 없습니다. 관리자 이메일 계정은 소유 확인이 없는 공개 가입보다 먼저 확보해야 합니다. 운영 전에 이메일 인증·비밀번호 복구와 실제 약관·개인정보 동의 UI 및 매장·사업자·환불 안내를 갖춰야 합니다. 현재 화면은 개발 버전임을 표시합니다.

## 주문과 스탬프 정책

- 매장 픽업 주문. 카드 결제 승인 후 유료 음료 1잔당 1개. 디저트·무료 음료 적립 제외.
- 스탬프 10개를 기본 사이즈 아메리카노 HOT/ICE 1잔과 교환. 사이즈업은 무료 교환 대상에서 제외.
- 무료 교환은 별도 주문으로 즉시 접수되며 카드 결제를 요구하지 않습니다. 20개면 두 번 교환 가능.
- 금액은 서버에서 계산하고 결제사 승인/조회로 검증합니다. 중복 승인과 동시 교환에 대해 DB 거래와 원장으로 중복 적립·차감을 방지합니다.
- 결제·준비 상태는 사용자가 새로고침합니다. 매장도 주문 관리 새로고침으로 최신 주문을 확인하세요. 자동 알림은 없습니다.
- 결제 확인이 지연되거나 브라우저를 닫은 경우 내 주문 또는 관리자 화면의 `결제 상태 확인`으로 복구합니다. 서버가 멈췄다면 서버 재시작 후 확인하세요. 결제 완료 주문만 음료를 준비하세요.
- 전체 취소는 관리자만 처리. 적립 회수와 교환 취소 반환은 각 한 번 처리합니다. 이미 쓴 적립 회수로 마이너스가 되면 향후 적립과 상계합니다.
- 외부 결제사 콘솔에서 취소해도 상태 확인 시 반영됩니다. 부분 취소 UI는 없으며 외부 부분 취소는 안전하게 해당 주문 적립 전부를 회수합니다. 서버 주기 동기화·웹훅은 아직 없으므로 외부 취소는 매장 상태 확인으로 반영해야 합니다.

## 파일 및 검증

- `menu.js`: 메뉴·가격 (메뉴 수정 후 서버 재시작. 기존 주문은 당시 가격 보존)
- `commerce.js`, `commerce.css`: 회원·장바구니·스탬프 화면
- `server.js`, `store.js`: API·인증·결제·DB 원장
- `admin.html`, `admin.js`: 매장 주문 관리
- `npm test`: 결제 모의 응답을 사용한 회원 인증·가격 조작·중복 적립·동시 교환·취소·복구 테스트

독립 AI 검토는 사용자 동의로 생략했습니다. 코드 변경은 커밋하거나 외부 공개하지 않았습니다.

## 페이지 이동
홈 `index.html` → 주문 `order.html`, 회원가입 `signup.html`, 로그인 `login.html`, 내 스탬프 `membership.html`로 각각 이동합니다. 주문 메뉴는 서버 설정이나 로그인 여부와 무관하게 볼 수 있고 담기도 가능합니다. 주문 중 로그인하면 장바구니를 보존하고 주문 페이지로 돌아옵니다. 계정과 실제 결제는 `start.bat` 실행 후 localhost에서 이용하세요.

## 폴더 정리
- public/: HTML·CSS·화면 JavaScript. 메뉴 수정은 public/menu.js.
- public/images/: 카페 이미지 원본. 평면도와 외관은 보관만 하고 서버에 공개하지 않습니다.
- data/: 회원·주문·스탬프 DB. 삭제하거나 GitHub에 올리지 마세요.
- test/: 자동 테스트.
- archive/backups/: 이전 작업 백업. Git에서 제외됩니다.
- server.js, store.js: 서버와 DB 처리.
- start.bat: 사이트 실행. npm start도 동일하게 사용합니다.
